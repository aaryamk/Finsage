# FinSage — Build Spec (PRD) for Replit Agent

> **Read this whole file before writing any code. Build everything in ONE pass. Do not ask clarifying questions — every decision is made below. If something is ambiguous, pick the simplest option and note it in `NOTES.md`.**

## 0. One-line pitch
**"Before making a big money decision, see what it does to the rest of your life."**
FinSage is a single-page web app for young Indian professionals. One shared financial profile feeds one calculation engine, which powers three connected tools: **Financial X-Ray**, **Life Decision Simulator**, and **Money Allocation Studio**.

## 1. Hard constraints (do not violate)
- **Frontend only.** React + Vite + TypeScript. No backend, no database, no auth, no API keys, no LLM calls.
- **Libraries allowed:** `recharts` (charts), `lucide-react` (icons). Plain CSS with CSS variables (no Tailwind, no UI kits).
- **All money math lives in `src/engine/` as pure, tested functions.** Components never contain formulas.
- **One source of truth:** profile lives in a single React context, persisted to `localStorage` (wrap in try/catch; app must work if storage fails).
- **No financial score** (no "82/100"). Findings only, each with evidence.
- Every screen shows the footer: *"Educational tool, not financial advice. Illustrative assumptions."*
- Indian number formatting everywhere: `₹1,20,000`, `₹14.85 L`, `₹1.2 Cr`.

| Pessimistic / optimistic return | 7% / 12% |
| Inflation | 6% / yr |

## 5. Calculation engine (exact formulas)
**EMI:** `emi(P, annualRate, years) = P*r*(1+r)^n / ((1+r)^n − 1)`, `r = annualRate/12`, `n = years*12`.
**Outstanding balance after k months:** `P*((1+r)^n − (1+r)^k) / ((1+r)^n − 1)`.

**Derived values (any profile):**
- `essentialOutflow = monthlyExpenses + existingEMIs` (plus new EMI in a home future)
- `monthlySurplus = monthlyTakeHome − essentialOutflow`
- `unallocated = monthlySurplus − monthlySIP`
- `emergencyMonths = liquidSavings / essentialOutflow`
- `jobLossRunway = (liquidSavings + investedCorpus) / essentialOutflow`

**FIRE age (monthly loop from current age to 70):**
- `corpus` starts at `investedCorpus`; grows at baseline monthly rate; `+ SIP` each month; SIP increases by `sipStepUpPct` every 12 months.
- `target(month) = 30 × 12 × retirementMonthlyExpenses × (1.06)^(month/12) + outstandingLoanBalance(month)`
- `retirementMonthlyExpenses = monthlyExpenses` (renter) or post-purchase expenses without rent (owner).
- FIRE age = first age where `corpus ≥ target`; otherwise show **"70+"**.

**Net worth timeline (yearly points, current age → 70):**
`liquid (grows 6%, plus unallocated surplus added monthly) + corpus + homeValue (grows 5%) − loanBalance`.

**Corpus range:** same projection at 7% / 10% / 12% → returns `{pess, base, opt}` at ages 40 and 60.

## 6. Screens

### Layout (all screens)
Top bar: logo "FinSage" + tagline + tabs **X-Ray · Decision Simulator · Allocation Studio · Roadmap**. Left: profile sidebar (280px). Main: content (max 1100px). Everything recalculates live on every input change (no "Calculate" buttons).

### 6.1 Financial X-Ray (default landing tab)
Heading: *"Here's what your money is telling us."*
Summary strip: counts → **Strong (n) · Watch (n) · Act now (n)**. No score.
Grid of finding cards. Each card = **title, status pill, evidence (with the actual numbers), consequence (one sentence), next step (one sentence + optional link to another tab).**

Rules (`runXRay`):
| # | Finding | Strong | Watch | Act now |
|---|---|---|---|---|
| 1 | Emergency fund (`emergencyMonths`) | ≥ 6 | 3–6 | < 3 |
| 2 | Idle cash: `liquid − 6×essentialOutflow` | ≤ 6 months' outflow extra | > 6 months extra → "₹X sitting beyond your buffer may be losing to 6% inflation" | — |
| 3 | Savings rate `(takeHome − outflow)/takeHome` | ≥ 30% | 15–30% | < 15% |
| 4 | Unallocated surplus (`unallocated`) | ≤ 10% of surplus | > 10% → link **"Plan it in Allocation Studio →"** | negative → "spending exceeds income" |
| 5 | Debt load `EMIs/takeHome` | < 30% | 30–40% | > 40% |
| 6 | Health cover outside employer | personal ≥ 5L | personal > 0 and < 5L | 0 → "Your only cover ends if you change or lose your job" |
| 7 | Life cover | dependents = 0 → Strong, "Not needed yet — revisit when someone depends on your income" | cover < 10× annual income with dependents | 0 cover with dependents |
| 8 | FIRE trajectory | FIRE age < 50 | 50–60 | > 60 or 70+ |

`runXRay` must accept ANY profile (including a post-decision future profile) — this is reused in §6.2.

### 6.2 Life Decision Simulator (flagship)
Heading: *"Compare two futures with the same assumptions."*
Decision type: **Buy a home** (only one; show a disabled chip "Career break — coming soon").
Controls: price slider ₹30L–₹1.5Cr (step ₹5L, default ₹55L), down payment 10–40% (default 20), interest 7–11% (default 8.5), tenure 10–30 yrs (default 20). Preset chips: **₹40L · ₹55L · ₹1Cr**.

`applyHomePurchase` returns Future B:
- `cashNeeded = price × (downPct + 0.07)`; `liquidSavings −= cashNeeded`
- `monthlyExpenses = monthlyExpenses − monthlyRent + price×0.002/12`; `monthlyRent = 0`
- add `newEMI` to outflow; `loan = price × (1 − downPct)`
- `monthlySIP = min(currentSIP, max(0, newSurplus))`

If `cashNeeded > liquidSavings`: show a **red banner** across Future B: *"Not enough cash for down payment + upfront costs — short by ₹X."* Still render the cards.

Two columns **Future A: Keep renting** vs **Future B: Buy this home**. Six outcome rows, each showing A value, B value, delta, and status colour:
1. Monthly surplus  2. Emergency fund (months)  3. SIP you can sustain  4. FIRE age  5. Job-loss runway (months)  6. Net worth at 40

Below: **Recharts line chart** "Net worth over time" — two lines (A and B), age on x-axis, ₹ Cr on y-axis.
Verdict box (rule-based sentence built from values), e.g. *"You can afford the EMI, but your emergency fund drops from 32.7 to 4.6 months and your job-loss runway halves."*
Button **"X-Ray this future →"** opens a right-side drawer with `runXRay(futureB)` findings.

### 6.3 Money Allocation Studio
Heading: *"Give every rupee of your surplus a job."*
Shows `monthlySurplus` at top. Five bucket sliders (₹0 → surplus, step ₹1,000):
**Emergency top-up · Insurance premiums · Loan prepayment · Short-term goal · Long-term investing.**
- Large stacked horizontal bar showing the split + **"Unallocated: ₹X"**. Sliders cannot exceed the remaining surplus (clamp).
- Preset chips: **Safety first** (40/10/0/20/30%), **Balanced** (15/10/0/20/55%), **Growth** (5/10/0/10/75%). Loan prepayment disabled with note "No loans" when `existingEMIs = 0`.
- Short-term goal inputs: name (default "Car down payment"), amount (default ₹3,00,000).

Outcome cards (live):
1. FIRE age (long-term bucket used as SIP)  2. Corpus at 40 and 60 as a **range** (pess / base / opt)  3. Emergency months in 12 months  4. Months to reach short-term goal (6% return)  5. Health cover status — "planned" if insurance bucket > 0.
Button **"Apply to my profile"** sets `monthlySIP = long-term bucket` → all other tabs update.

### 6.4 Roadmap
Four horizontal phase cards; Phase 1 highlighted with badge **"You are here"**:
1. **Decision workspace** — manual profile, calculation engine, FIRE projection, SIP comparison, emergency-fund model, one linked life-decision simulator.
2. **Personal financial intelligence** — saved plans, investment import, portfolio analysis, full Financial X-Ray, tax and insurance tools, scenario history.
3. **Connected financial life** — consent-based Account Aggregator integrations, live cash flow, detection of meaningful changes, proactive reviews.
4. **Assisted action** — regulated partnerships for professional advice, products and approved actions.
Below: principles strip — *One source of truth · Deterministic math · Visible uncertainty · India-specific rules · Privacy by consent · Clear regulatory boundaries.*

## 7. Design system
Tone: calm, trustworthy, editorial — closer to a well-designed annual report than a trading app. Lots of whitespace, no gradients, no emoji.
```css
:root{
  --bg:#F7F6F2; --surface:#FFFFFF; --ink:#16181D; --muted:#6B6F76; --border:#E6E3DC;
  --accent:#1F4D3A; --accent-soft:#E6EFEA;
  --strong:#1E7A4C; --watch:#B7791F; --act:#C0392B;
  --strong-bg:#E8F4EC; --watch-bg:#FBF1E1; --act-bg:#FBE9E7;
  --radius:12px; --shadow:0 1px 2px rgba(0,0,0,.04),0 4px 16px rgba(0,0,0,.04);
}
```
- Fonts (Google Fonts): **Inter** for UI; numbers use `font-variant-numeric: tabular-nums`. Headings Inter 600, letter-spacing −0.01em.
- Big numbers on outcome cards: 28px/600. Labels: 13px uppercase muted, letter-spacing .04em.
- Status always shown as **pill + word** (Strong / Watch / Act now), never colour alone.
- Deltas: "↑ / ↓" with colour by whether the change is good or bad (not by sign).
- Number changes animate (150ms fade). Sliders show the live value in a chip.
- Responsive: under 900px the sidebar becomes a top accordion, the A/B columns stack, cards go single-column. 16px side gutter, no horizontal scroll.
